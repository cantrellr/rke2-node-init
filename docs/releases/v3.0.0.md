# rke2-node-init v3.0.0

Release date: 2026-06-24

## Release theme

`v3.0.0` introduces production-style single-node RKE2 cluster support while preserving the existing air-gapped image, registry, server, agent, and verification workflows.

The major operator-facing change is that `bin/rke2nodeinit.sh` is now the public kind-driven entrypoint. Operators can supply an `rkeprep/v2` manifest and let the manifest `kind:` choose the right workflow.

```bash
sudo bash bin/rke2nodeinit.sh -f <rkeprep-v2-manifest.yaml> -y
```

## Highlights

### Single-node cluster kinds

New explicit `rkeprep/v2` kinds:

- `singleNodeImage`
- `singleNodeServer`

These are designed for replacement clusters, edge/lab clusters, low-footprint development clusters, and production-like non-HA environments where deterministic recovery and secure bootstrap matter.

### Public dispatcher with preserved core

`bin/rke2nodeinit.sh` is now the canonical entrypoint for both legacy and single-node flows.

The previous large implementation is preserved in `bin/rke2nodeinit-core.sh`, and helper scripts now organize single-node, config, CNI, YAML/router, and system concerns.

### COTPA single-node replacement configuration

This release includes COTPA replacement-cluster manifests for:

- `dc1manager`
- `dc1domain`
- `dc2domain`
- `dc3domain`

The manifests intentionally reuse replacement-cluster IP addresses and define explicit service/cluster CIDRs and cluster DNS.

### Single-node preflight guards

The single-node server flow installs preflight controls for common bootstrap blockers:

- CIS profile sysctls:
  - `vm.overcommit_memory=1`
  - `kernel.panic=10`
  - `kernel.panic_on_oops=1`
- swap-off before `rke2-server` starts
- stale unsupported `import-images:` key cleanup from RKE2 config files
- low-resource packaged add-on HelmChartConfig manifests
- default network policy guardrail
- secrets encryption and snapshot defaults

### Bootstrap fixes from real node validation

This release incorporates fixes discovered during single-node validation:

- Prevent kubelet startup failure caused by reserved Kubernetes role labels in `spec.node-label`.
- Prevent kubelet startup failure caused by active Ubuntu `/swap.img`.
- Prevent RKE2 CIS startup failure caused by missing host kernel parameter values.
- Prevent RKE2 startup warnings/failures from stale unsupported `import-images:` config keys.
- Prevent CNI permission remediation from waiting behind `rke2-server` / `rke2-agent`.

### CI and policy updates

- CI now accepts `singleNodeImage` and `singleNodeServer` as valid `rkeprep/v2` kinds.
- IPAM CI now skips dependency installation when the installable IPAM package is absent.
- Repository security policy, contribution guidance, issue templates, PR template, and CODEOWNERS were added or refreshed.

## Upgrade notes

### Existing multi-node users

Existing `Image`, `Push`, `Server`, `AddServer`, `Agent`, `Verify`, `Airgap`, and `CustomCA` flows remain supported.

Existing multi-node manifests do not need to adopt `singleNodeImage` or `singleNodeServer`.

### Single-node users

Use the public entrypoint:

```bash
sudo bash bin/rke2nodeinit.sh -f configs/single-node/golden-image.yaml -y
sudo bash bin/rke2nodeinit.sh -f configs/single-node/production-server.yaml -y
```

For COTPA replacement clusters:

```bash
sudo bash bin/rke2nodeinit.sh -f configs/cotpa-single-nodes/image-hyperv-v1.35.5+rke2r2-singlenode.yaml -y
sudo bash bin/rke2nodeinit.sh -f configs/cotpa-single-nodes/nodes/dc1manager.yaml -y
sudo bash bin/rke2nodeinit.sh -f configs/cotpa-single-nodes/nodes/dc1domain.yaml -y
sudo bash bin/rke2nodeinit.sh -f configs/cotpa-single-nodes/nodes/dc2domain.yaml -y
sudo bash bin/rke2nodeinit.sh -f configs/cotpa-single-nodes/nodes/dc3domain.yaml -y
```

Run only the node manifest that matches the VM being provisioned.

## Validation

Validation performed during the release cycle included:

```bash
bash tests/test-single-node-profile.sh
sudo bash bin/rke2nodeinit.sh -f configs/cotpa-single-nodes/nodes/dc1domain.yaml -y
make kubeconfig
kubectl get nodes -o wide
kubectl get pods -A
sudo rke2 etcd-snapshot ls
sudo rke2 secrets-encrypt status
```

Observed single-node bootstrap result included a Ready `dc1domain` node with `control-plane,etcd` roles on RKE2 `v1.35.5+rke2r2`.

## GitHub release command

After the release prep is merged and tagged:

```bash
git checkout main
git pull --ff-only
git tag -a v3.0.0 -m "rke2-node-init v3.0.0"
git push origin v3.0.0
bash scripts/package-release.sh v3.0.0
gh release create v3.0.0 \
  dist/rke2-node-init-v3.0.0.tar.gz \
  dist/rke2-node-init-v3.0.0.zip \
  dist/rke2-node-init-v3.0.0.sha256 \
  dist/rke2-node-init-v3.0.0.manifest.txt \
  --title "rke2-node-init v3.0.0" \
  --notes-file docs/releases/v3.0.0.md \
  --latest
```

## Rollback

If the release needs to be withdrawn before consumers adopt it:

```bash
gh release delete v3.0.0 --yes
git push origin :refs/tags/v3.0.0
```

If the code has already been merged and needs reverting, revert the release-prep merge commit and any post-release fixes separately.
